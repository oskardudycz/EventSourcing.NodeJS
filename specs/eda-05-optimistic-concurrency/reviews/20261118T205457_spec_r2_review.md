### Q&A-1. Node.js async change leaves out the saga, the to-do list and the projection

Quote: Solution: "Every facade method, every bus handler in the wiring and every test in 02–04 is `async` and awaits these calls. Nothing else in 02–04 changes". AC 1.2: "every handler subscribed in the wiring awaits the facade or bus call it makes." AC 2.4: "each sending its commands through the bus and returning nothing". Q40 reading: "Every facade method, the wiring and the tests in 02–04 … are async and await them."
Consequence: Node.js 02–04 code that calls the database or bus but is neither a facade nor a wiring lambda: the 03 and 04 `GroupCheckoutSaga` handlers (subscribed directly; `onGuestCheckedOut` calls `messageBus.publish(...)` without returning it), the 03 to-do list `handle` / `tryComplete`, `core/projection.ts` `Projection.handle` (`get` / `store` / `delete`), `ScheduledGroupCheckoutToDoList.handleAll` (`findAll()`), and the projection subscription in `scheduledBusinessProcess.solved.test.ts`. Kept synchronous, `projection.handle` gets a promise, `groupCheckout !== null` is always true, and unawaited saga publishes finish after the test's `await`, so expected messages can be missing. "Returning nothing" conflicts with a saga handler that must return the publish promise.
Belongs to: spec
Resolution: fixed in r3: all Node.js 02–04 code that calls the database or bus is async and awaits, saga handlers return the publish promise; .NET and JVM unchanged (Oskar: "What about .NET and JVM?"; checked, Node.js only).

### Quality-3. Node.js saga handlers "return nothing", but the async bus has to await them

Quote: AC 2.4: "each sending its commands through the bus and returning nothing"; AC 1.2: "every handler subscribed in the wiring awaits the facade or bus call it makes"; "`publish` returns a promise and awaits each handler it calls".
Consequence: The Node.js 04 saga handlers `onGuestCheckedOut` / `onGuestCheckoutFailed` call `messageBus.publish(...)` in a block body and are subscribed directly. Belongs to: spec
Resolution: fixed in r3: same as Q&A-1.
