### Q&A-1. Neither infrastructure solution can apply the missing-entity rule "in the facade's function" as written

Quote: AC 15.3: "the command handler loads the state or starts from `initial`, calls the function". AC 15.4: "the aggregate store loads the aggregate, runs the function". AC 15.5: "the facade's function applies the missing-entity rule (group 12) ... the aggregate store and command handler only load, store and retry". Decision: "Node.js immutable guest stay facades stop loading `initial` for anything but check-in."
Consequence: The function can't tell `initial` from a real state in .NET (`Initial` is a default record) and JVM (no `initial`); the aggregate store has nothing to call the function on for a missing aggregate. A developer guesses per repository: missing-entity logic in the store/handler, null/Optional to the function, or a "not existing" state in JVM and .NET.
Belongs to: qa
Resolution: fixed in r14: Oskar, "we can pass initial as in decider"; immutable entities get the initial state, aggregates "nothing stored" (Q62).
