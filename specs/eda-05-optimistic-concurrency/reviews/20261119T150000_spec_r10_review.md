### Quality-1. The parallel-transactions criterion passes with the copy-and-merge design Q52 rejected

Quote: AC 2.16: "WHEN two transactions run at the same time, one storing D1 and the other D2, THEN after both commit the collection returns D1 and D2".
Consequence: With new, separate documents, a copy-and-write-back implementation passes, yet it undoes another transaction's change to a document both copied.
Belongs to: spec
Resolution: fixed in r11: the criterion has T1 change an existing X while T2 stores D2; after both commit, X is T1's.

### Quality-2. The 05 conflict criterion can't show that "none of its changes" is applied

Quote: AC 2.16 (05): "THEN the transaction fails with `ConcurrencyException` and none of its changes is applied".
Consequence: With one change, partial application can't be seen, and there's no end state to assert.
Belongs to: spec
Resolution: fixed in r11: the transaction also stores a new E; after the failure the collection returns D' at version 2 and no E.
