### Step-3.1. `batchSize: 1` is a production setting, added only to make tests fast

Quote: `application.ts`: `pulling: { pullingFrequencyInMs: 20, batchSize: 1 },`; progress: "It is a throughput limit for production; Emmett has no lower backoff ceiling option."
Consequence: every processor in production reads one message per poll, so throughput drops for every operation; only the tests need it, and the application has no option to set it from `testApplication`.
Belongs to: implementation
Resolution: fixed

### Step-3.2. In `in-memory` mode the unpaid-orders worker writes `CloseUnpaidOrder` straight into the channel

Quote: `messagingBus === 'none' ? eventStore.appendToStream(OrderId.streamNameOf(orderId), …) : appendToChannelStream(eventStore, channelStreamName(ordersInternalChannel), …)`; spec L48: "stores `CloseUnpaidOrder` in the order's stream for the orders handler"; Q22 (a).
Consequence: the worker skips the order's stream and the forwarder (Q22 option b, rejected); with Kafka and RabbitMQ it would publish directly; delivery is tied to `MESSAGING_BUS` instead of the Q40 setting; in `none` the command is stored without `kind: 'Command'`.
Belongs to: implementation
Resolution: fixed

### Step-3.3. The handler's appends lose the handled message's correlation and causation (Q31)

Consequence: order events get a new correlation id, and their causation id is not the command's id, so the checkout → order chain breaks (22.4 in step 5 will assert it).
Belongs to: implementation
Resolution: fixed

### Step-3.4. The `createEventStoreInSession` stop-gap goes against the spec and spreads into public APIs

Consequence: the spec says the opposite; a new store is built per handled command; a test-only hook enters production options, and `getApplication`'s new type moves away from Emmett's shape and the step-8 branch (Q49); `recordAppendsInto` has no test of its own.
Belongs to: spec, qa
Resolution: from Q61 item 2: stop-gap kept until #432, spec updated

### Step-3.5. Without a broker, a reactor runs commands that the workflow relays to its own module

Resolution: from Q61 item 1: the workflow decides commands and the handler records events

Resolution: Fixed: `recordAppendsInto` is deleted (RR-2/Q71); published messages come from Emmett's `WrapEventStore` appends.
