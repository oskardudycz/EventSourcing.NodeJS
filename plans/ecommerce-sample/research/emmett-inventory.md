# Emmett inventory for the e-commerce port

This file lists what Emmett has today and where the gaps are for a port of the Java e-commerce sample (shopping carts, orders, payments, shipments, a process with compensation, Kafka and RabbitMQ, forwarders, timeout workers, read models, OpenTelemetry, message versioning, API black-box tests).

Baseline: Emmett `origin/main`, version `0.43.0-rc.3`, commit `0b9b5c7b` ([package.json](https://github.com/event-driven-io/emmett/blob/0b9b5c7b/src/packages/emmett/package.json#L4)). All code links point to that commit. Work that is not on main is in a separate section and is labelled so.

When a claim could not be checked in code, it says "not verified".

### Error handling, locks, partitioning

- A handler returns nothing (continue), `SKIP` or `STOP` ([processors.ts#L278-L291](https://github.com/event-driven-io/emmett/blob/0b9b5c7b/src/packages/emmett/src/processors/processors.ts#L278-L291)). A thrown error becomes `STOP` and the checkpoint stays at the last successful message ([processors.ts#L662-L687](https://github.com/event-driven-io/emmett/blob/0b9b5c7b/src/packages/emmett/src/processors/processors.ts#L662-L687)). There is no built-in retry policy, dead-letter queue or poison-message handling for processors. The shared tests show the pattern "record the failure as an event and carry on" ([reactorErrors.features.ts#L181-L249](https://github.com/event-driven-io/emmett/blob/0b9b5c7b/src/packages/emmett-tests/src/errorHandling/reactorErrors.features.ts#L181-L249)).
- Processor lock with policy `fail`, `skip` or `retry` ([processorLock.ts#L11-L37](https://github.com/event-driven-io/emmett/blob/0b9b5c7b/src/packages/emmett/src/processors/processorLock.ts#L11-L37)). PostgreSQL has a lock implementation ([postgreSQLProcessorLock.ts#L47](https://github.com/event-driven-io/emmett/blob/0b9b5c7b/src/packages/emmett-postgresql/src/eventStore/projections/locks/postgreSQLProcessorLock.ts#L47)). Advisory locks break with AWS RDS Proxy ([#328](https://github.com/event-driven-io/emmett/issues/328)).
- `partition` is the tenant/module partition of the store. No key-based partitioning or parallel consumers per key was found (not verified beyond the option list).

### Forwarder, outbox, brokers

- No Kafka, RabbitMQ, SQS, NATS or other broker integration exists. A search of the snapshot for these names finds only the docs sentence about possible future consumers ([testing.md#L110](https://github.com/event-driven-io/emmett/blob/0b9b5c7b/src/docs/guides/testing.md#L110)).
- No outbox table and no forwarder component. The closest pieces:
  - `onAfterCommit` + `forwardToMessageBus`: best effort, not durable (see section 1).
  - `onBeforeCommit` in PostgreSQL and SQLite: runs in the append transaction, so a user can write their own outbox rows there.
  - A reactor that reads the store and publishes to a broker: a "forwarder" built by hand on the consumer, with checkpoints. This is the store-as-outbox pattern; Emmett gives the reading and checkpointing, not the publishing.
- The workflow docs call the workflow stream its "inbox" and "outbox" ([workflows.md#L62](https://github.com/event-driven-io/emmett/blob/0b9b5c7b/src/docs/guides/workflows.md#L62)). That is a stream, not a broker outbox.

## 10. Almanac

Almanac is a small observability library that Emmett uses and re-exports ([package.json#L5](https://github.com/event-driven-io/emmett/blob/0b9b5c7b/src/packages/almanac/package.json#L5), [emmett observability index](https://github.com/event-driven-io/emmett/blob/0b9b5c7b/src/packages/emmett/src/observability/index.ts#L1)). It has:

- `Tracer`, `Meter` (counter, histogram, gauge), `Logger` and `ObservabilityScope` abstractions with no-op defaults ([tracer.ts#L5-L17](https://github.com/event-driven-io/emmett/blob/0b9b5c7b/src/packages/almanac/src/tracers/tracer.ts#L5-L17), [meter.ts#L1-L25](https://github.com/event-driven-io/emmett/blob/0b9b5c7b/src/packages/almanac/src/meters/meter.ts#L1-L25), [scope.ts#L42-L73](https://github.com/event-driven-io/emmett/blob/0b9b5c7b/src/packages/almanac/src/scopes/scope.ts#L42-L73)).
- Providers: OpenTelemetry (`otel()`, `otel-node` SDK setup), Pino, console ([otel.ts#L16](https://github.com/event-driven-io/emmett/blob/0b9b5c7b/src/packages/almanac/src/providers/otel/otel.ts#L16), [otelNode.ts#L30](https://github.com/event-driven-io/emmett/blob/0b9b5c7b/src/packages/almanac/src/providers/otel/node/otelNode.ts#L30)).
- Optional peer dependencies on `@opentelemetry/*` and `pino` ([package.json#L107-L114](https://github.com/event-driven-io/emmett/blob/0b9b5c7b/src/packages/almanac/package.json#L107-L114)).
- Test helpers (collecting tracer and meter, span and meter assertions) and graceful shutdown ([observabilitySpec.ts#L57](https://github.com/event-driven-io/emmett/blob/0b9b5c7b/src/packages/almanac/src/testing/observabilitySpec.ts#L57), [gracefulShutdown.ts#L11](https://github.com/event-driven-io/emmett/blob/0b9b5c7b/src/packages/almanac/src/lifecycle/gracefulShutdown.ts#L11)).

The package has no README in the snapshot.
